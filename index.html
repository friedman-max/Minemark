02 / THE PROTOCOLMINEMARK-RETRIEVE-V1

An open world.
A precise objective.

Minecraft leaves room for many solutions. The finish line stays fixed: obtain a specific item and keep it in your inventory.

The protocol is designed to make attempts repeatable while leaving the agent’s strategy open.

01

Start from zero.

A fresh agent session. A restored world snapshot. An empty inventory. Every scored attempt begins at the same defined starting point.

CONTROLLED START
02

See. Think. Act.

The agent uses the game screen, keyboard, and mouse. Navigation, crafting, mining, and recovery are all part of the task.

VISIBLE CONTROL ONLY
03

Check the result.

A specified item and quantity, visibly retained in inventory. Record the outcome and evidence; keep setup failures out of the score.

BINARY COMPLETION
≡ Evaluation specificationv0.1 +
Primary objective
Retrieve at least 1 coal and retain it in inventory.
Environment
Random-seed Survival world, Peaceful difficulty, no bonus chest, commands disabled. Reuse a clean snapshot for comparable attempts.
Run budget
15 minutes in the current coal protocol. Pilot timing is not comparable or reported as a score.
Restricted access
No game commands, world-save inspection, seed lookup, inventory APIs, external notes, or evaluator output.
Required isolation
A new agent task, a clean world snapshot, an empty player inventory, and no prior run context.
Record
Target, quantity, outcome, verification evidence, termination reason, and isolation status. Secondary measures only when reliably recorded.

03 / WHY MINEMARK

The next move
is the test.

Knowing how to craft a pickaxe is one thing. Finding wood, navigating a landscape, making the tool, and recovering when a plan fails asks something more.

Minemark studies that gap between knowing and doing. Our starting point is item retrieval: a compact way to observe planning, spatial reasoning, and tool use through a clear outcome.
